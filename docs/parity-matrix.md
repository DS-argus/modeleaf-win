# Modeleaf Windows parity matrix

**Baseline:** Modeleaf v0.10.0, immutable commit [`0f7ff0b54c3674c48f6b555261f939397cfbfb88`](https://github.com/DS-argus/modeleaf/tree/0f7ff0b54c3674c48f6b555261f939397cfbfb88). Golden source links are indexed in [`windows-porting/source-index.md`](./windows-porting/source-index.md). This matrix reports observable Windows implementation evidence, not planned work.

**Last audited:** 2026-09-14 for Issue #71 operator acceptance and packaged fixture/cursor verification; older Issue #53 and phase evidence remains historical and does not certify all current packaged behavior.

**Issue #53 reader-stability revalidation:** reported interactive defects supersede historical parity claims for open/recents, rendering, navigation, and search. These surfaces remain `partial` until the revised reader passes packaged Windows checks. Document geometry is independent of raster residency; measured page sizes are retained; repeated page input is coalesced; verified resident-page landings publish active-page state; destruction uses the PDF.js loading task; recent clearing uses an atomic native transaction. TOC and keyboard hints are retired under the explicit owner-approved delta.

`tools/qa/reader-stability.html` exercises real PDF.js, text layers, and session behavior in hidden Chromium with the fixed 300-page fixture. Forward/reverse scrolling, repeated document-edge input, mixed navigation, Fit Page followed by eight zoom changes, cross-page search, and empty-resource teardown have renderer-level evidence. In-memory native authority means this **does not prove packaged WebView2 transport, native keyboard routing, native state events, DPI, or OS integration**. Those checks remain pending.

Issue #53 owner follow-up: real user testing confirmed recent clearing but exposed hidden-host first-open positioning and active-tab-close restoration gaps. The follow-up requires zero-size → visible opening coverage, successor visibility before activation, and preserves normal zoom/navigation anchors. Open now defaults to `Ctrl+Shift+O` (ADR 0001); Browse has no glyph and a conditional Recent divider; regular tabs use equal `184px × 26px` slots. Shortcut/platform parity remains pending native revalidation; explicit user keymap overrides are not rewritten.

Issue #53 chooser baseline at `6771bbf` exposes a native-generated bounded display-only `displayPath`; opening uses only opaque `recentId`. Directory middle-truncation and font fitting preserve the filename; Browse retains keyboard focus without its border. That baseline passed 87 frontend files/885 tests and148 top-level Rust tests plus local gates. Its hidden Chromium evidence is in `docs/evidence/issue53-recent-paths.json`; those counts do not certify subsequent retirement or packaged Windows behavior.

Issue #53 retirement implementation `fda61e08b322fcf93230522131687394d80bb42d` passed 77 frontend files/801 tests,148 top-level Rust tests, build/fmt/clippy/diff, and current hidden reader/chooser scenarios. `docs/evidence/issue53-retirement.json` records verified ordinary-click page-two landing/history/indicator, exact11605→11605 tab restoration, search, continuous geometry and forced-color containment. It also records the repaired registry self-wait and overlay Escape ownership findings. Native acceptance remains pending; no new executable or publication is claimed.

Issue #53 centered-link/indicator-retirement implementation `c939f9e3754c7da0c3a93a624f8d724e9b0e22b2` supersedes that indicator behavior under owner comment5611619154. The complete local gate passed75 frontend files/777 tests and146 top-level Rust tests (plus two nested helper invocations), build/fmt/clippy/diff. [`issue53-link-landing.json`](./evidence/issue53-link-landing.json) records actual-click centering within0.459px, immediately visible next-page raster/text, boundaries/history, raw-scroll and mixed-height ownership regressions, indicator absence, fixture hashes and CLEAR rereviews. Browser DPR simulation is not native certification; the prior application was not replaced and packaged acceptance remains pending.

**Issue #71 Browse pointer verification:** the earlier owner-thread/posted dispatcher did not fix the user symptom. Disabling WebView2 `HideCursorWhileTyping` for initial and additional windows leaves OS settings and Enter/focus dispatch unchanged. The operator reported that the presented physical input/selection/cancellation/two-window checklist worked on the hash-verified production candidate. [Retained evidence](./evidence/issue71-cursor.json) separates that manual attestation from same-executable A/B, state-isolated packaged native trials, cursor-inclusive OS recording, and unchanged fixture SHA. Existing owner/latch/admission contracts remain intact. This closes the specific cursor verification gap, not all Open/Recent or release gates; the broader feature row remains `partial`.

Issue #73 removes synthetic idle/hover borders, fill and shadows from ordinary PDF link hit targets while preserving explicit positive annotation borders and keyboard focus. On `links.pdf` (SHA-256 `dd5e2d598fa9e0bcae25e488541a898220d38b791991bc95796d7ba5f30044d4`), real Chromium with the production content controller reproduces four erroneous 2px boxes before the change and zero-width transparent targets afterward; hover, 2px keyboard focus and emulated forced-colors 3px focus pass. The browser reader harness also verifies internal click/history, external authorization callbacks and zero retained reservations. A standalone Windows debug build opened the unchanged fixture through native argv; its captured page shows no synthetic boxes and the process closed normally. This is limited fixture-backed evidence, not certification of the reporter's PDF, all DPI/theme combinations, source-authored positive border appearance, or native high-contrast behavior. Feature §7/W08 remain `partial`; no broader parity status is promoted.

Issue #78 adds persistent typed `FIT PAGE`/`FIT WIDTH`/`SEARCH` badges to one footer renderer. Owner follow-up adds FIT WIDTH and removes duplicate fit wording from ordinary page status; the fit badges are mutually exclusive and either can coexist with SEARCH. Pending prefixes coexist with diagnostics; search clear removes only search-owned wording; active-tab changes cancel pending input. [`issue78-fit-width.json`](./evidence/issue78-fit-width.json) records the superseding follow-up evidence and links the initial verification. Native 100/125/150/200% monitor/text-scale/high-contrast and Narrator audit remain pending; view/search/input rows remain `partial`. The action registry, keymap, PDF raster/navigation algorithms and persistence contracts are unchanged.

## Status vocabulary

| Status | Meaning |
|---|---|
| `not-started` | No implementation evidence for the surface. |
| `partial` | Some implementation exists, but the complete golden acceptance contract is not evidenced. |
| `parity` | All golden behavior and evidence gates are demonstrated. |
| `intentional-delta` | The approved Windows behavior differs from macOS; ADR 0001 defines it. |
| `blocked` | A prerequisite measurement or platform gate prevents an implementation decision. |

No row is marked `parity` without fixture-backed, platform-appropriate evidence. `.internal/docs/windows-parity-ledger.md` is **historical v0.5.0 evidence only**, is not an authority, and cannot establish a status in this matrix.

A feature row cannot be `parity` while any phase it depends on is unfinished. Several rows below therefore stay `partial` even though their delivered phases passed, because a later phase still owns part of the surface.

## Action-count reconciliation

The macOS v0.10.0 baseline freezes **61** action identifiers. The Windows contract contains **51**: seven `pane.*` actions plus `toc.toggle`, `toc.scrollDown`, `toc.scrollUp`, `link.hint` and `indicator.picker` are excluded. Of these, **45 are configurable** and four are fixed prompt/search bindings. `tests/contract/snapshots/action-ids.json` is the Windows authority; historical macOS counts are unchanged. The defaults fingerprint is `ea7b922dd96632e1a4a35df4e148f55f9b1ddc224dd7d61549242b60ef0f5344`.

## Immutable supersession closure

The immutable macOS source remains the reference for exact-duplicate annotation deduplication, captured viewport landings, the61-action baseline, literal400ms prefix behavior, notify-only update supersession and embedded-outline semantics. Windows applies the twelve explicit action exclusions in ADR0001. TOC/hint/indicator implementations are redevelopment references, not current support claims.
